# Composition: automatic Image production

The **Композиция / Composition** button in Image opens an automatic creative workspace. The ordinary model/mode form remains available through **Обычный режим / Standard mode**. Composition is an orchestrator, not another checkpoint or an entry in `image_registry.ENGINES`.

The person describes the desired picture, optionally adds materials, chooses **1–5 variations** and optionally square/landscape/portrait format. There is no Ultra switch: supported quality profiles always use the maximum-quality policy. Gemma chooses models and an ordered chain for each variation, using current readiness and the researched Image model guides. It may use one network or several; more processing is not inherently better.

The planner receives each engine's dated `local_rating` alongside capabilities and known limitations. These small visual samples inform task selection; native pixel count alone is not a quality score. FIBO Dev is available for one-megapixel photographic generation and edits with at most four sources, with separate enlargement when helpful.

## Materials and variations

| Group | Limit | Meaning |
|---|---:|---|
| Heroes | 6 | People/characters to carry into each result |
| Places | 4 | Location, landscape or interior |
| Objects | 8 | Vehicles, devices and other supplied things |
| References | 4 | Scene/composition base or style/content donor, as described by the person |

All groups are optional. Each shows its existing photos plus **one empty slot** until full. Labels explain who/what a photo represents. Intake uses the shared Image converter; one upload is at most 100 MiB, all stored draft materials at most 200 MiB. Drafts, labels and descriptions persist across reloads; a draft nobody touched for seven days (a started composition touches its draft) and run folders beyond the newest 30 are removed when the workspace opens, since every finished image also lives in the ordinary Image output folder and history. A start must name an existing draft: without one it used to make an empty draft and compose without the person's photos. No voices/video/models are uploaded here.

Every variation must use every supplied material somewhere in its chain; missing material IDs invalidate the plan. Later stages take the previous result first, so they cannot accidentally discard the preceding stage by starting from unrelated photos. Model limits still apply: Klein/Qwen 2.1 up to ten inputs, Edit 2511 three, Z-Image text generation without references or one-source Detail/Tile. Within the ordinary editing modes, code derives Single/Reference/Multi from the validated input count: real Gemma twice called a two-input edit Multi. A style-only plan also repeated one donor as two inputs even on retry; identical IDs now collapse to one input, with drafted picture references remapped together. The chosen model and requested edit remain. Opaque material IDs in unquoted prompt prose become `Picture N` using that stage's source order; quoted lettering is unchanged. Large material sets require stages, with **at most 12 per variation**. Identical variation plans are rejected. This validates routing, not whether a network actually drew every person/object correctly.

The reference's role is free: the request can make it the receiving scene or take only its style/content. The planner selects source roles; validation uses oriented width/height to put an already matching material first in the initial stage when available. Numeric and ordinal input references are remapped together, quoted lettering stays literal, and repeating normalization does not renumber twice. Later stages keep `previous` first. This avoids synthetic side bands when, for example, a landscape place already fits but Gemma chose a square receiving reference first. It does not change which reference supplies the layout.

First-image aspect controls edit outputs (Klein and Qwen 2.1 draw on the shape of the first picture and normalise it to about one megapixel), so `composition_media.prepare` fits it to the shared canvas presets in `composition_plan`: within 6 % it scales to fill with a small edge crop; otherwise it fits whole over a blurred copy (a transparent picture over a transparent frame). A note explains temporary padding and requested edits; it no longer unconditionally protects objects the user wants replaced. The first version left 69 % grey around a 1152x768 photo on a landscape canvas. Blurred continuation worked in Director keyframes, but one real four-source Composition retained blur bands, prompting the alignment guard above. Original files remain unchanged. Prepared inputs are bounded for the ordinary Image route.

## Quality and execution

Requested Cyrillic lettering is allowed in an intermediate text-only stage as well as the final stage. A real two-stage still life was refused because the first stage's quote guard had an empty request; it now uses the root's exact lettering allowlist without demanding every word in each intermediate picture or accepting invented Cyrillic. The repaired chain (Klein 2K/x2 → Qwen 2.1 2K) completed in 484 s on the installed ComfyUI 0.44.0 backend, preserving one apple and **УТРО**. The plan still chose an enlargement before a later lower-resolution stage: chain economy remains a limitation; local ratings do not force a universal favourite.

- Qwen 2.1 uses 40 steps; Edit 2511 uses Standard 40/CFG 4, without automatically enabling its community LoRA; Klein retains its 16-step distilled preset; Z-Image retains its trained preset; [FIBO 2.0 Dev](models/image/image-fibo2-dev.md) uses its non-distilled 50-step/CFG 5 profile, RGB near 1 MP with at most four inputs. Gemma cannot select a speed profile.
- Explicit transparent-output requests require an alpha-capable final stage in every variant: currently Qwen 2.1. RGB assembly stages may precede it, but an RGB Detail/Tile tail cannot erase its alpha. A real planner selected Klein for a genuine transparent PNG despite the model summaries; validation now rejects that impossible plan with a specific retry reason. Shared intent detection excludes quoted lettering and negated transparency requests.
- Qwen's automatic alpha wrapper at the final rewrite follows the original human intent, not an invented alpha cue in a child step. This prevents code from reinforcing that particular plan conflict; it does not remove arbitrary contradictory prose Gemma may still produce. A tested white-background plan added an unnecessary refinement and conflicting transparency wording, so chain economy and general semantic fidelity remain limited.
- Native high-resolution generation and x2/x4 AI Upscale are available where supported; the finished picture may not exceed 16 megapixels (native megapixels times the upscale squared: 4K is the largest that was ever run), and a Qwen 2.1 stage with more than three inputs stays at one megapixel because that model gives every picture the selected pixel budget. The planner chooses them when useful; extra resampling can harm writing, identity and alpha edges, so it is not forced onto every stage. Detail/Tile retain their actual required x2 path.
- A plan that fails validation is sent back to Gemma once with the exact reason. The planner is explicitly given valid native-resolution/upscale pairs and the 16 MP output formula. Once the plan exists the panel shows "stage n of N; about M minutes in all". The rough estimate uses graph costs, material-observation batches and per-reference preparation; 2026-11-05 four-input preparation took about 155 s per stage, exposing the old flat 45 s underestimate. Cold HDD loads and concurrent GPU use can still change wall time substantially.
- Each stage calls **`/api/generate`** (a busy answer, 409, is waited out for up to ten minutes as in the Director), then status/result/cancellation routes. Existing per-model prompt preparation, component policy, GPU admission, saving, Image history and event identities all apply. No direct worker/model calls or automatic model downloads.
- The authenticated final content stage of each variant receives the original human request as `composition_intent`; a trailing Detail/Tile also receives it to preserve that content. Earlier assembly stages and unrelated requests do not. A real plan omitted full-body framing in its second variant, and the child rewriter previously knew only that incomplete draft. `composition_sources` maps actual picture numbers to original upload group/index/label, including the already composed `previous` image. `composition_variant` gives this separate image's number and total: a real two-angle request leaked both views into one caption, so rewriters must retain the current variant's view without merging separate results. The context budget includes the extra intent/source data. A bounded text-only fidelity pass reconciles the final caption with that intent after vision; a real pass restored a lost standing pose. Final lettering checks include the original request, excluding quoted upload-group references such as `from photo «Герои»`; actual requested lettering stays protected. These checks preserve information, not a guarantee that a model obeys every semantic constraint.
- The coordinator's `composition` reservation lasts across planning and all stages. Authenticated loopback requests use the same `X-VisualForge-Run` mechanism as the Director, with a separate private token. Other modules cannot enter the gaps. Child operations inherit the composition event scope.
- Local Stop and global Stop stop planning/preparation and the active image. A late Gemma answer cannot enqueue an image after cancellation. Existing completed variations remain visible after a later failure or Stop.

The ordinary Image output folder is respected. Individual Image steps retain their normal history/saved outputs. Composition additionally keeps final PNGs and provenance in `UserData/Composition/runs/<id>/`, with immutable material snapshots, original request, checked plan, steps, child job IDs and final result metadata. Its panel provides previews, PNG downloads and the latest 30 runs. Finished cards persist across status refreshes so polling cannot steal keyboard focus from a download. Captions and alt text use localized variation numbers; free Gemma plan titles remain provenance because real titles misdescribed content. Reopening after a studio restart marks unfinished work interrupted rather than pretending it resumed.

Atomic JSON replacement briefly retries Windows permission errors (10 attempts, 50 ms apart): a real audit reader without delete sharing blocked `run.pending` → `run.json`. The old complete record survives until replacement succeeds; persistent denial is still reported. A real Windows lock/release probe and CPU regressions verify this file behaviour without another GPU run.

## Implementation and verification

`App/server/composition/`:

- `composition_plan.py`: request limits, ready-model capabilities, plan validation and fixed quality policy.
- `composition_media.py`: grouped materials, labels, snapshot paths and full-frame input fitting.
- `composition_brain.py`: bounded batches of material observations, then Gemma planning with one retry; `GemmaTask`, English model instructions and original-language lettering.
- `composition_studio.py`: Image calls through the Director's existing loopback transport.
- `composition_manager.py`: sequential run, reservation, durable status/history and cancellation.
- `composition_routes.py`: same-origin bounded endpoints for profile/draft/materials/start/status/result/history/cancel.

The bridge initializes the manager lazily when the workspace is opened, so importing it for tests does not create composition data in the installed studio. UI: `App/frontend/composition-panel.js` / `.css`; strings: `App/strings/composition-strings.json`.

**2026-11-05 CPU regression:** transparent material previews now composite onto a neutral matte before Gemma observes them. Previously RGB conversion exposed hidden colour from fully transparent pixels as a false scene background; a minimal test reproduced the failure before the fix. Original material bytes and alpha remain untouched. The planner's capability summaries now include the scoped real Image findings (successful transfers as well as Klein's two ignored small edits and 2511's rendered-looking text-only fox). This informs role selection without treating a single rating as the best model for every task. Real Composition qualification is recorded in the [ongoing UI audit](VisualForge-Image-UI-Audit-2026-11-05.md).

**CPU evidence (2026-11-01):** 21 focused plan/media/manager/bridge tests passed with fake Gemma/ComfyUI, including the real route chain Klein → Edit 2511, maximum profile dispatch, grouped intake, distinct variations, material coverage, source snapshots, aspect fitting, partial results, interrupted runs, authenticated reservation and late-answer cancellation. The related Image, prompt-manager, Gemma, GPU admission, event/generation identity, bridge, localization and Director regression checks also passed after a dynamic localization-key fix (328 distinct tests overall, with affected checks rerun). Ruff F/B/E9 for Composition and its tests, F/E9 for bridge/GPU/history integration, JavaScript syntax, generated string validation, source guard and whitespace checks passed. These establish software behaviour, not generated quality.

**Audit of 2026-11-02 (CPU and a browser check, no GPU):** found and fixed the grey frame above, the silent start without a draft, the generic validation message, a refused start on a momentary 409, no limit on the size of an upscaled picture, a GET for a material that made an empty draft, a run file that could not be read stopping the workspace from opening, no clean-up of drafts and runs, and no sign of progress or duration (panel: a fake running status showed "stage 3 of 4; about 9 min"). 10 tests were added (31 in all). Not changed on purpose: a variation that fails ends the composition (the finished ones stay), because a failure of the card would repeat for the rest. Not run: any real Gemma plan or image of a composition, so the real effect of the blurred margin on Qwen models, of the Gemma plans on the 16-megapixel and one-megapixel rules, and of the estimate is **[unknown]**.

**Historical UI evidence:** a browser CPU fixture with synthetic images and fake model responses verified two hero uploads with exactly one next slot, three results from six sequential Klein/2511 stages, planning cancellation without another queued image, RU/EN changes, reload persistence, history previews and return to ordinary Image. No browser console errors were observed. These were software checks without real generation.

**2026-11-05 real GPU/UI evidence:** the owner approved the timed sequential run. During active generation a finished download retained keyboard focus across status polling; numbered captions/alt were checked in RU/EN. Root intent and source numbering fixes improved specific outputs; complex four-source results from both Klein and a direct Qwen 2.1 diagnostic still cropped legs or lost receiving-scene geometry despite faithful captions. Exact likeness and six-person quality remain unqualified.
