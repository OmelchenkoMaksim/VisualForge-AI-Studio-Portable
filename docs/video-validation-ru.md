# VisualForge AI Studio — Video в staging

Проверено 2026-10-24T12:28:15.841644+00:00. Версия **2026.10.24-video.2-preview**. Статус **READY FOR STAGING**: локальная генерация и экспорт работают на RTX 5070 Ti 16 ГБ. Основная установка не обновлялась. Это preview с ограниченным набором проверенных профилей, а не объявление готовности всех возможностей H3.

Исходники сохранены в локальном Git, ветка `codex/video-preparation`, commit кода `7a03bff82938e684ecce6fe10856572e57c977af`. Исторический исходный репозиторий был удалён пользователем; текущая Git-история восстановленной копии не подменяет утраченные commit.

## Что реализовано

В одном интерфейсе появились Image / Video, реестр Video-движков, отдельный backend с запуском по требованию и частный Python. Image и Video получают GPU последовательно: конфликтующие запросы отклоняются, Image-модели освобождаются перед Video, сторонние процессы не завершаются. Отмена и закрытие родительского процесса ограничены собственным деревом Windows Job Object.

Добавлены промпт, исходный/конечный кадр, проверенные профили качества, seed без потери 64-битной точности, настоящий прогресс по журналам движка, время выполнения, MP4-плеер, экспорт, история, архив промптов и отдельная папка Video. Промпт сохраняется при переключении разделов и режимов. Результат Image можно передать в Video копией; исходный PNG не изменяется. Неподдерживаемые режимы и сочетания качества не выдаются за готовые.

Истории, архивы и настройки папок разделены по модулям для сохранности существующих данных Image. Общей объединённой ленты всех Image/Video задач пока нет. Явно выбранный внешний абсолютный путь сохраняется. Сохранение MP4 использует исключительное создание файла, поэтому существующие результаты не перезаписываются.

Image после Video реально создал и автоматически сохранил новый PNG Qwen 2.1; затем этот PNG использован для I2V. Конфликтующие запросы Image→Video и Video→Image получили HTTP 409. Существующие Image workflows и их параметры не изменены.

## Проверки и обнаруженные ошибки

- 30 целевых тестов прошли в фактическом embedded Python 3.13. Проверены валидация, 64-битный seed, сохранность архивов Image, повреждённая история, Unicode-пути, внешний output, коллизии имён, ограничение длинного профиля, освобождение GPU-заявки при ошибке подготовки и очистка собственного процесса с сохранением постороннего контрольного процесса. JavaScript прошёл синтаксическую проверку.
- Отмена реальной Video-задачи через UI завершила её со статусом cancelled; VRAM вернулась примерно к 1,1 ГБ. Принудительный OOM не провоцировался, восстановления после настоящего OOM не проверяли.
- Отсутствующий и повреждённый Video-runtime проверены двумя отдельными процессами bridge: Video возвращает ошибку, Image preflight/history/settings продолжают работать.
- Исправлены несовместимый способ передачи пути кодировщика и обработка пустого успешного ответа ComfyUI `/free`. Недостающие таблицы High размещены в кеше, таблицы refinement установлены из уже загруженных файлов. Неуспешные попытки сохранены как FAIL, без переименования в PASS.
- Первая GPU-проверка Unicode-пути завершилась ошибкой CUDA при загрузке cubin. Исправление: только временные кеши компиляции CUDA/Triton/Inductor при необходимости располагаются в ASCII-пути пользовательского Temp на C, отдельно для установки. Веса, настройки и результаты остаются в portable-каталоге. Повторная генерация из каталога с кириллицей завершилась успешно; модели возвращены на исходное место.
- Offline-проверка: локальные веса, HF offline flags, запрет исходящих Python-соединений и штатных загрузок FreeVideo. Успешные финальные задания завершены с этим ограничением. Это не тест физически отключённого адаптера и не изменение Windows firewall/DNS.
- Штатный неизменённый EXE запущен в отдельной staging-копии: оба Image-движка готовы, Video доступен, MP4 из истории воспроизводится. Журнал подтвердил максимизированное окно. Процессы теста остановлены собственным Job Object; production не изменён.

## Пакет, откат и бюджет

Архив `VisualForge-2026.10.24-video.2-preview.zip` содержит App, частный Runtime/Video и Models/Video/H3. Размер архива: **55,183,350,171 байт**. Файлов полезной нагрузки: **34732**. SHA-256 архива: `02013874c7a59b245667b64ebe79f84d8336410bf0b746e563c1d683226dacef`. Контрольные суммы файлов, CRC ZIP и отсутствие повторяющихся ZIP-имён проверены. Последние небольшие изменения текста ошибок и оформления отдельно проверены в браузере.

Python-инструмент установки проверяет весь payload и текущую базу до записи, отказывается заменять неизвестные/новые исходники, создаёт новый backup текущих заменяемых файлов и InstalledRelease.json, ведёт журнал намерений и отказывается при откате перезаписывать последующие правки. UserData, существующие Image-модели и Image-runtime не входят в изменяемые пути.

Репетиция установки и отката проверила все реальные файлы App; перенос Runtime/Video и Models/Video/H3 проверялся небольшими синтетическими компонентами. Все прежние файлы восстановлены побайтно, backup сохранён. Полную повторную копию 50+ ГБ весов в этой репетиции не делали. Отдельно runtime готового пакета распакован и реально исполнил GPU-задачу из нового Unicode-пути.

Всего получено при загрузках: **53,218,622,644 байт**, включая повторные передачи; предел **200 000 000 000**. Логическая сумма всех каталогов этой работы, кешей, staging и архива: **175,047,600,169 байт**. Жёсткие ссылки при этом консервативно посчитаны повторно. Точный снимок — `video-staging-validation.json`. Новый объём production этим снимком не считается: установка туда не выполнялась.

Для production требуется новое отдельное разрешение пользователя. Перед ним нужен свежий план по фактическим хешам и свободному месту; существующие staging, модели, UserData и backup автоматически не удаляются. Предыдущая авторизация на удаление старой установки не использована повторно.
